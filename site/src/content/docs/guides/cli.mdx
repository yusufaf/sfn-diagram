The package ships a CLI for use without writing any JavaScript:

<PackageManagers type="dlx" pkg="sfn-diagram" pkgManagers={['npm', 'pnpm', 'yarn', 'bun']} args="state.asl.json --format svg -o diagram.svg" />
<PackageManagers type="dlx" pkg="sfn-diagram" pkgManagers={['npm', 'pnpm', 'yarn', 'bun']} args="state.asl.json --format mermaid > diagram.mmd" />

```bash
cat state.asl.json | npx sfn-diagram - --format svg
```

Piped through any runner works the same way — swap `npx` for `pnpm dlx`, `yarn dlx`, or `bunx`.

| Flag | Description |
|---|---|
| `--format <svg\|mermaid\|png\|html>` | Output format (default: `svg`) |
| `-o`, `--output <path>` | Output file (required for `png`; stdout otherwise) |
| `--theme <light\|dark\|path>` | Color theme for SVG/PNG/HTML: a built-in name, or a path to a [custom theme JSON file](#custom-theme-files) (default: `light`) |
| `--layout <TB\|LR\|RL\|BT>` | Graph direction (default: `TB`) |
| `--hide-catch` | Drop error-handler (`Catch`) branches |
| `--hide-variables` | Drop the `$var` annotations for ASL `Assign` blocks |
| `--hide-comments` | Don't use a state's `Comment` as its node label |
| `--collapse[=names]` | Collapse `Parallel`/`Map` containers into placeholders. Bare flag collapses every container; `--collapse=Name1,Name2` collapses only those. Write `\,` for a comma inside a state name |
| `--show-icons` | Draw [AWS service icons](/guides/configuration/#aws-service-icons) on Task states |
| `--icon-position <left\|top\|right>` | Icon placement relative to the label (default: `left`) |
| `--icon-size <pixels>` | Icon size in pixels (default: `24`) |
| `--show-state-types` | Draw each state's type as a label on the node |
| `--edge-style <straight\|curved\|orthogonal>` | Edge path style (default: `curved`). `orthogonal` currently renders the same as `straight` — see [#323](https://github.com/yusufaf/sfn-diagram/issues/323) |
| `--style-preset <aws-standard\|enhanced>` | Node shapes: AWS parity, or a distinct shape per state type (default: `aws-standard`) |
| `--catch-label-style <error-type\|catch-number>` | Label on `Catch` edges: the error name, or `Catch #N` (default: `error-type`) |
| `--node-width <pixels>` | Width of each state node (default: `120`) |
| `--node-height <pixels>` | Height of each state node (default: `60`) |
| `--node-separation <pixels>` | Separation between nodes within a rank (default: `50`) |
| `--rank-separation <pixels>` | Separation between ranks (default: `50`) |
| `--padding <pixels>` | Padding around the diagram (default: `20`) |
| `--diagram-title <text>` | Accessible name, rendered as the SVG's `<title>` and `aria-label` |
| `--diagram-description <text>` | Accessible description, rendered as the SVG's `<desc>` |
| `--background-color <color>` | PNG background (default: `transparent`) — see the [note below](#background-color-and-the-theme) |
| `--diff <baseline>` | Compare the input (head) against a baseline definition |
| `--execution <history.json>` | Overlay a `GetExecutionHistory` result on the diagram |
| `--resolve-cfn` | Treat the input as a CloudFormation/SAM/CDK template |
| `--resource <logicalId>` | State machine to extract when the template has several |
| `--check` | Lint the definition instead of drawing it — see [Linting](#linting) |
| `-h`, `--help` / `-v`, `--version` | Show help / version and exit |

## Custom theme files

`--theme` takes a built-in name (`light` or `dark`) or a path to a JSON file holding a
[`CustomTheme`](/guides/configuration/#themes). Any value that isn't `light` or `dark` is
read as a path:

```bash
sfn-diagram state.asl.json --theme ./brand.theme.json -o diagram.svg
```

```json title="brand.theme.json"
{
  "base": "light",
  "background": "#fbfbfd",
  "fontFamily": "Inter, system-ui, sans-serif",
  "nodeColors": {
    "Task": { "fill": "#eef2ff", "stroke": "#4338ca" },
    "Choice": { "fill": "#fefce8", "stroke": "#a16207" }
  }
}
```

Every field is optional. `base` picks which built-in theme supplies the ones you leave
out, so a file naming only `nodeColors.Task` is a one-colour tweak to the light theme
rather than a theme built from nothing.

A missing file, malformed JSON, or a top-level value that isn't an object is a usage
error: the CLI writes `Error: Cannot read theme file <path>: <reason>` to stderr and
exits `2`.

## Background color and the theme

`--background-color` is applied by the PNG rasterizer, beneath the rendered SVG. The
built-in `light` and `dark` themes paint their own background across the full canvas, so
that rectangle covers whatever the rasterizer put behind it and the flag has no visible
effect. To use it, give the theme a transparent background:

```bash
sfn-diagram state.asl.json --format png --theme ./transparent.theme.json \
  --background-color '#ffffff' -o diagram.png
```

```json title="transparent.theme.json"
{ "base": "light", "background": "transparent" }
```

## Exit codes

Every invocation exits with one of three codes, so a script can tell a mistake in the
command from a failure while running it without parsing stderr.

| Code | Meaning |
|---|---|
| `0` | Success. Also a deliberate no-op: [`comment gitlab`](#comment-gitlab) on a pipeline with nothing to do, and `--check` finding nothing worse than a warning. |
| `1` | **Runtime failure.** The invocation was valid, but something went wrong: an input that could not be read or parsed, a template with no extractable state machine, an unreadable `--theme` file, a missing optional peer dependency, a failed write. Also `--check` finding at least one error-severity diagnostic. |
| `2` | **Usage error.** The invocation itself cannot work: an unknown flag, an invalid value, a blank value, a combination that is contradictory, or a required flag left out. Nothing about the input file would change the outcome. |

Nothing else is ever returned.

### `--check` shares 1 on purpose

`--check` lints instead of drawing, and exits `1` when it finds an error-severity
diagnostic — a finding, not a malfunction, and the same code a linter uses for the same
reason. That is why usage errors live on `2`: it leaves `1` free to mean "I ran and the
answer was no" without colliding with "you invoked me wrong".

```bash
sfn-diagram state.asl.json --check
case $? in
  0) echo "clean (or warnings only)" ;;
  1) echo "lint errors found" ;;
  2) echo "bad invocation" ;;
esac
```

### Which code a bad path gets

A path that cannot be read is a runtime failure, not a usage error — the command was
well formed and the filesystem was not cooperative:

```bash
sfn-diagram missing.asl.json                 # 1
sfn-diagram state.asl.json --diff gone.json  # 1
sfn-diagram state.asl.json --theme gone.json # 1
```

A misspelled `--theme` lands in the same place, because `--theme` accepts either a
built-in name or a path and the two are indistinguishable once the read fails. The
error message names all the accepted forms for that reason:

```
$ sfn-diagram state.asl.json --theme ligth
Error: Cannot read theme file ligth: ENOENT: no such file or directory, open '…/ligth'
--theme takes light, dark, or a path to a theme JSON file.
```

### In CI

```yaml
- name: Render the diagram
  run: |
    if ! sfn-diagram state.asl.json -o diagram.svg; then
      case $? in
        2) echo "::error::sfn-diagram was invoked incorrectly - check the flags" ;;
        *) echo "::error::sfn-diagram failed to render - check the definition" ;;
      esac
      exit 1
    fi
```

## Diff and execution overlays from the CLI

```bash
# Highlight what changed between two revisions of a definition
npx sfn-diagram head.asl.json --diff base.asl.json -o diff.svg
npx sfn-diagram head.asl.json --diff base.asl.json --format mermaid > diff.mmd

# Colour a diagram by what actually happened in a run
aws stepfunctions get-execution-history --execution-arn "$ARN" > history.json
npx sfn-diagram state.asl.json --execution history.json -o run.svg
```

Both flags support `--format svg`, `--format mermaid`, and `--format html` only, and
cannot be combined with each other. The change/status summary is written to **stderr**,
so the diagram on stdout still pipes cleanly:

```
Diff summary:
  Added:     NewStep
  Modified:  StepB
  Removed:   StepC
  Unchanged: 1
```

`--execution` accepts either a full `GetExecutionHistory` response (`{"events": [...]}`)
or a bare events array. See [generateDiff](/reference/index/functions/generatediff/)
and [generateExecution](/reference/index/functions/generateexecution/) for the
programmatic equivalents.

CloudFormation/SAM/CDK templates work as input too — see [Extracting ASL from a CDK/CloudFormation template](/reference/cfn/functions/extractaslfromtemplate/).

> **`--format png` needs the optional `@resvg/resvg-js` peer.** It is not installed by default. With `npx`, run `npx --package sfn-diagram --package @resvg/resvg-js sfn-diagram …`; in a project, `npm install @resvg/resvg-js`. Without it the CLI exits with an actionable error. Or skip the install entirely with the [Docker image](#docker), which ships it preinstalled.

## Linting

`--check` runs [`lintAsl`](/reference/index/functions/lintasl/) on the input and prints every
finding to stderr instead of a diagram. The exit code is `1` when any finding is an
error, `0` otherwise, so it drops straight into a pre-commit hook or CI step:

```bash
npx sfn-diagram state.asl.json --check
```

```
error   /States/Ship/Next  State "Ship" sets both "End: true" and "Next"  [end-with-next]
warning /States/Audit  State "Audit" is unreachable from StartAt "Validate"  [unreachable-state]
1 error, 1 warning
```

Each line is `severity`, a JSON Pointer to the offending value, the message, and the
rule code. `--resolve-cfn` / `--resource` work the same way they do for rendering;
`--check` cannot be combined with `--diff`, `--execution` or `--output`.

## `comment gitlab`

`sfn-diagram comment gitlab` posts (or updates) a diagram/diff on a GitLab merge
request from CI — see [GitLab CI](/ecosystem/gitlab/) for the full workflow, the
options, and the Mermaid size limit it works around.

```bash
sfn-diagram comment gitlab --help
```

## Docker

A prebuilt image is published to GitHub Container Registry with the PNG rasterizer preinstalled, so `--format png` works out of the box — no browser, no extra install:

```bash
docker run --rm -v "$PWD":/work ghcr.io/yusufaf/sfn-diagram:latest \
  /work/state.asl.json --format svg -o /work/diagram.svg

docker run --rm -v "$PWD":/work ghcr.io/yusufaf/sfn-diagram:latest \
  /work/state.asl.json --format png -o /work/diagram.png
```

Tags: `latest`, `<major>`, `<major>.<minor>`, `<major>.<minor>.<patch>`.

PNG text is rendered with Liberation Sans, which the image ships. To use your own fonts, mount them and point the renderer at them with `SFN_DIAGRAM_PNG_FONT_DIRS` (a `:`-separated list of directories) or `SFN_DIAGRAM_PNG_FONT_FAMILY`.

## Standalone binary

Each GitHub release also attaches single-file executables for Linux (x64, arm64),
macOS (Apple silicon, Intel), and Windows (x64) that need no Node.js:

```bash
brew install yusufaf/tap/sfn-diagram
# or download sfn-diagram-<os>-<arch> from the releases page and chmod +x it
```

They support every format except `png`: the native rasterizer it needs cannot be
bundled into a single-file executable. Use the Docker image above or the npm
package with `@resvg/resvg-js` installed. See
[Use from Python, Go, Java, and other languages](/guides/other-languages/).
